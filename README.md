# labwork-Lifecycle

### Виконавець: Данчевський Владислав Олегович

Тема проекту: **Система контролю прострочених бібліотечних видань**.

Опис: Програма призначена для контролю видачі бібліотечних видань та відстеження книг, термін повернення яких був порушений. Система дозволяє бібліотекарю зберігати інформацію про книги, читачів, видачу видань та автоматично визначати прострочені повернення.

Обрані технології:

  1. Laravel Framework (backend)
  2. React Framework (frontend)
  3. MySQL (storage)

Чому саме ці технології?
*сучасні*, *цікаві для мене*, *вивчаю їх*, *працюю з ними*.

**Функціональні вимоги:**

Додавання та збереження даних- Система повинна дозволяти бібліотекарю додавати інформацію про книги, читачів та видачу видань.
- Дані повинні зберігатися у постійному сховищі (базі даних).
Редагування та видалення інформації- Система повинна дозволяти змінювати або видаляти інформацію про книги, читачів та записи видачі.
Пошук та фільтрація даних- Система повинна надавати можливість пошуку книг за назвою або автором.
- Користувач повинен мати можливість переглядати список прострочених видань.
Автоматична перевірка термінів повернення- Система повинна порівнювати дату повернення книги з поточною датою.
- У разі перевищення терміну повернення книга повинна отримувати статус «прострочена».
Формування звітів- Система повинна створювати звіт про прострочені книги.
- Звіт повинен містити інформацію про назву книги, читача та кількість днів прострочення.

**Нефункціональні вимоги:**

1. Зручність використання
   - Інтерфейс програми повинен бути простим та зрозумілим для користувача без спеціальної підготовки.
2. Надійність
   - Система повинна забезпечувати збереження даних та не допускати їх втрати після завершення роботи програми.
3. Швидкодія
   - Основні операції (пошук, додавання, редагування даних) повинні виконуватися за короткий час.
4. Безпека даних
   - Система повинна перевіряти коректність введених даних та не дозволяти створення некоректних записів.
5. Масштабованість
- Система повинна мати можливість розширення у майбутньому (наприклад, додавання нових функцій або збільшення кількості записів у базі даних).

**User Stories**
1. Додавання нового видання
Як бібліотекар, я хочу додавати нові книги до системи, щоб мати актуальний список бібліотечних видань.
Критерії приймання:
- Користувач може ввести назву книги, автора, жанр та рік видання.
- Після збереження книга з’являється у списку видань.
- Система не дозволяє додати книгу без обов’язкових полів.

2. Перевірка прострочених книг
Як бібліотекар, я хочу бачити список прострочених книг, щоб контролювати своєчасне повернення видань читачами.
Критерії приймання:
- Система автоматично порівнює дату повернення з поточною датою.
- Прострочені книги відображаються окремим списком.
- Для кожної книги показується кількість днів прострочення.

3. Формування звіту про заборгованість
Як бібліотекар, я хочу створювати звіт про неповернені книги, щоб швидко отримувати інформацію про читачів із простроченнями.
Критерії приймання:
- Система формує список читачів, які мають прострочені книги.
- У звіті відображаються назва книги, дані читача та дата повернення.
- Користувач може переглянути готовий звіт у програмі.
